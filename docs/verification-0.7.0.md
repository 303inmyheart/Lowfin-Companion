# Local verification: Companion 0.7.0

- Release build: .NET 10, Jellyfin.Controller 12.2.0, embedded dashboard HTML and original Lowfin L SVG/WOFF2. Built locally; GitHub Actions is not used.
- 111 .NET tests passed with Jellyfin 12.2 packages and 111 with 12.3 packages. Includes future-version eligibility, user mapping isolation, movie/episode/live-TV payloads, timestamps, paused playback, coalescing, bounded EPG queries and programme changes, stale stop events, configuration disable, opt-in artwork registration/cache and original completion/cache/index/provider regressions.
- Dashboard DOM behavior passed using jsdom 26: five sections, unique control IDs, load/save, unknown-field preservation, independent tag switches, mappings, duplicate-user validation and interval limits. Local Firefox preview checked for spacing and field layout; it uses a lightweight preview skin rather than the complete Jellyfin web application.
- Two repository-generator tests passed: flat package layout/checksum/history and URL validation.
- Full plugin loaded as Active in an isolated Jellyfin 12.2 server. Existing native integration checks passed using a twelve-hour sample: completion correction, resume, regular playback events, manual fences, library isolation, authentication, incremental changes, provider access and cover tags.
- Native dashboard endpoints checked: sidebar registration/private glyph, embedded font/SVG, configuration defaults, managed CSS add/remove preserving other CSS, manual Discord mappings and removal of the standalone-import UI/API. No production server was modified.
- Actual ClientWebSocket tests against a local server exercise HELLO/IDENTIFY, a fragmented 2 MiB READY, queued presence publication, stop/clear, client headers and authentication close code 4004 without token logging or repeated authentication retries.
- A full 12.3 server load and a real Discord connection were not exercised. The 12.3 result is API/package compatibility testing. Future server API changes can still require an update despite the removal of the upper version gate.
- Release packaging generates flat/manual ZIPs and the matching Jellyfin manifest together. Release publication uploads those exact bytes; the feed retains previous versions.

- Discord token tests: durable key-ring reopening, plaintext migration, encrypted serialization, idempotent saves, normalized user binding, wrong-user/missing-key/tamper rejection, Unix permissions and service-side decryption before mocked gateway creation. Dashboard tests cover ciphertext preservation, blank-field retention and required replacement on user change. Native test checks startup migration, API/XML encryption and key-directory permissions with fake tokens only.

- Artwork pipeline tests use the actual upstream renderer with Jellyfin's Skia native library: local season cover, local series fallback, remote series source, decoded 512 × 512 PNG upload, correct multipart MIME, no Discord authorization sent to the image/upload host, external-asset registration and persisted cache reuse after reopening the service. HTTP image/upload/Discord responses are simulated; no real external cover uploads are performed. A separate playback test covers transient registration failure, bounded retry without seek, and no duplicate unchanged activity.
